# Shop UI

Все операции с виджетами и состоянием редактора выполняются в клиентском потоке.

## Экран и расширения

`ShopScreen` владеет каталогом, панелью инструментов и оверлеем. Каждый экземпляр
создаёт собственные виджеты. `createScreen()` собирает описание UniGUI без открытия
окна, `open()` открывает его через игровой backend. Закрытие backend вызывает
освобождение ресурсов. После `close()` экземпляр нельзя открыть повторно.

Для расширения экрана регистрируйте **фабрики** `ShopScreenElement`, а не общие
экземпляры виджетов:

```java
ShopScreen screen = ShopScreen.builder()
        .element(context -> root -> {
            Button clearSearch = new Button("Clear search");
            ShopStyles.button(clearSearch);
            clearSearch.onClick(event -> context.search(""));
            root.addChild(clearSearch);
            return clearSearch;
        })
        .build();
screen.open();
```

Фабрика получает `ShopUiContext` конкретного окна: поиск, переключение избранного
и `ShopModalHost`. `priority()` задаёт порядок размещения, меньшие значения идут
первыми; одинаковые сохраняют порядок регистрации. `dispose()` освобождает ресурсы
элемента в обратном порядке, в том числе при ошибке сборки экрана.

Модальные окна открывайте через контекст владельца. Для покупки используйте
`new ShopPurchaseModal(card, context)`: диалог сохраняет владельца, поэтому смена
активного экрана не переносит его тултипы в другое окно.

`ShopScreenController` остаётся фасадом стандартного окна для существующих сетевых
и cache-callback. В новом коде элементов используйте переданный контекст.

## Данные каталога

- `ShopOfferView` — контракт представления: заголовок, фабрики виджетов и группы оплаты.
- `ShopOfferPresentation` — имя, фабрики компонентов, группы оплаты и форматирование.
- `ShopCatalogItem` — метаданные и фабрики компонентов без создания виджетов.
- `ShopCatalogQuery` — поиск, фильтрация категорий и стабильная сортировка избранного.
- `ShopPurchasePolicy` — клиентская проверка условий и баланса. Окончательное решение
  о покупке принимает существующая серверная логика.

Списки в группах оплаты и новых снимках защищены от структурного изменения.
Старые обращения `ShopCatalogElement.CostEntry` и `.CostGroup` остаются доступны
через унаследованные типы; новые импорты используют `ShopOfferView`.

### Рендер компонентов и аддонов

Карточка, предварительный просмотр редактора и окно покупки вызывают
`ShopComponent.createRender()`. UI не определяет, является ли результат предметом,
валютой, скидкой или новым типом аддона. Компонент возвращает произвольное дерево
`Widget` со своими размерами и оформлением. Например, в классе компонента аддона:

```java
@Override
@Environment(EnvType.CLIENT)
public Widget createRender() {
    VBox content = new VBox();
    content.addChild(new Label("Custom service"));
    content.addChild(new Button("Service details"));
    return content;
}
```

Каждый вызов должен создавать **новое дерево**, а не возвращать сохранённый виджет:
карточка и диалог покупки отображаются одновременно. `null` означает отсутствие
видимого элемента; UI ничего не подставляет взамен. Порядок соответствует порядку
компонентов предложения. Компоненты без визуального представления используют
стандартную реализацию, возвращающую `null`.

В карточке область товаров имеет фиксированную высоту 46 UI-пикселей. Элементы
располагаются одним рядом по центру. При переполнении появляется горизонтальная
прокрутка; количество товаров не увеличивает высоту карточки. Внутреннюю компоновку
собственного виджета аддон задаёт сам.

Для бейджей компонент возвращает `ShopBadge` либо использует
`ShopRenderWidgets.badge(text)`. Бейджи находятся отдельным рядом под товарами,
над разделительной линией и оплатой. Несколько бейджей сохраняют порядок компонентов.
В окне покупки бейджи находятся над основным рядом содержимого.

`ShopRenderElement` — фабрика, а `ShopComponentPanel` — её владелец в конкретном
представлении. Панель освобождает дерево через `dispose()` и обслуживает вложенные
`ShopItemWidget` с тултипами. Компоненты с собственными подписками или иными ресурсами
освобождают их в `dispose()` возвращаемого виджета. Область товаров в карточке ограничена фиксированным viewport;
в диалоге компоненты находятся в прокручиваемой области.

Компоненты `CostComponent` остаются внутри своих групп оплаты и тоже используют
`createRender()`, в том числе в меню выбора оплаты. Стандартная реализация стоимости
собирает строку из необязательного `getRenderIcon()` и числового количества. Аддон
может переопределить весь рендер. Доступность оплаты определяется собственным
`canPay(player, amount)`, а не распознаванием типа стоимости в UI.

В `ShopCatalogItem` нет фиксированных полей `rewards` и `discountPercent`.
Старые конструкторы предметных превью преобразуют данные в фабрики; для новых
интеграций используйте конструктор с `List<ShopRenderElement>`. Старые типизированные
accessor-методы сохранены как устаревшие вспомогательные методы и не управляют рендером.

## Редактор

`ShopEditorState` координирует сессию, выбор объекта и уведомления. Команды разделены:
`offerEditor()`, `categoryEditor()`, `currencyEditor()`. Существующие методы состояния
делегируют этим сервисам. Для отдельной сессии доступен `ShopEditorState.create()`;
встроенные представления редактора продолжают использовать `ShopEditorState.get()`.

Для подписки используйте `subscribe(callback)` и сохраняйте `ShopUiSubscription`.
Вызывайте `close()` у подписки в `dispose()` представления. Повторное закрытие
безопасно; две регистрации одного callback имеют независимый жизненный цикл.

## Стили и указатель

`ShopTheme` и `ShopStyles` задают оформление магазина. `ShopEditorTheme` содержит
палитру редактора, `ShopEditorStyles` — оформление его контролов, а внутренний
`ShopEditorRenderers` — отрисовку. `UnityStyles` сохранён как устаревший фасад.
Явно оформленные поверхности отключают стандартную тему UniGUI.

Для кнопки с декоративной строкой иконок и текста используйте `ShopContentButton`.
Он измеряет содержимое с учётом padding и исключает его из hit testing через
неинтерактивный контейнер. Поэтому hover, click и курсор принадлежат всей кнопке.
Внутрь такого содержимого нельзя помещать самостоятельные интерактивные контролы.
